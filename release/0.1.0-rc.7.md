# Teum 0.1.0-rc.7

Status: unpublished release candidate prepared for maintainer review on 2026-08-16.

## Highlights

- Pinned every public shadcn install command to `shadcn@4.18.0`.
- Pinned every external dependency inside the versioned registry to its reviewed lockfile version while keeping internal dependencies on the same `@teum-pinned` release scope.
- Added an append-only registry history ledger covering all 11 version directories; release-anchored versions are compared with their source commit byte-for-byte.
- Pinned every GitHub Action to a full commit SHA, disabled persisted checkout credentials, and isolated Pages and package-attestation authority from dependency and build steps.
- Made package-candidate assembly produce an exact one-tarball file set with a CycloneDX SBOM, manifest, and checksums before isolated attestation.
- Made local RC assembly refuse dirty trees or existing outputs, build in a fresh staging directory, validate its exact file set, and publish atomically to the ignored artifact directory.
- Added consistent hosting security headers, separate mutable/immutable cache contracts, and a hard 404 boundary for missing registry routes.
- Added an adopter evaluation guide, structured adopter-feedback form, and factual launch drafts without manufacturing adoption or publication evidence.

## Install one component

```bash
npx shadcn@4.18.0 registry add @teum-pinned=https://teum.minwookshin.com/r/v/0.1.0-rc.7/{name}.json
npx shadcn@4.18.0 add @teum-pinned/button
```

The command was executed in a fresh React + TypeScript + Vite consumer. The exact result is recorded in `release/quickstart.json`.

## Security and integrity

The registry release manifest records exact installer and external dependency versions plus SHA-256 metadata for each artifact. The package workflow can attest only the single tarball named by its candidate manifest. npm publication remains disabled.

## Remaining external gates

- independent consumer adoption;
- Edge and broader branded-browser coverage;
- physical touch, virtual keyboard, and safe-area review;
- independent accessibility review and broader assistive-technology coverage;
- production p75 performance evidence;
- maintainer-approved tag, GitHub prerelease, and any future npm publication.

Passing automated checks does not close these gates.
